# Eman Dawara — API-first Real Estate Marketplace

مشروع Laravel 12 تجريبي يوفّر API بإصدارين متزامنين (`/api/v1` و`/api/v2`) فوق منطق أعمال مشترك. في V1 يكون السعر رقمًا وتكون العملة بحقل منفصل، بينما يعيد V2 السعر ككائن `{amount, currency}`. لكل إصدار Resources خاصة، وبطاقات القوائم أخف من صفحات التفاصيل.

## المتطلبات

Laravel 12 وPHP 8.2 أو أحدث وComposer 2. يحتاج التشغيل إلى MySQL وRedis. أسهل خيار هو Docker وDocker Compose.

## التشغيل عبر Docker

من مجلد المشروع نفّذ:

```bash
cp .env.example .env
docker compose up --build
```

بعد جاهزية MySQL، تثبّت الحاوية الحزم، وتنشئ مفتاح التطبيق، ثم تشغّل migrations وseeders. العنوان المحلي هو `http://localhost:8000`.

ينشئ الـSeeder حسابات تجريبية مثل `agent1@eman-dawara.test` وكلمة المرور `password`. رمز Sanctum الخاص بالحساب الأول هو `eman-dawara-demo-token-1`. هذه بيانات محلية للتجربة فقط؛ لا تستخدمها في بيئة إنتاج.

للتشغيل اليدوي ثبّت الحزم عبر `composer install`، انسخ `.env.example` إلى `.env`، ثم نفّذ `php artisan key:generate` و`php artisan migrate --seed`، وبعدها `php artisan serve`. تأكد أن إعدادات MySQL وRedis في `.env` تطابق بيئتك.

## المسارات

- `GET /api/v1/properties` و`GET /api/v2/properties`: فلاتر اختيارية هي `province_id` و`offer_type` و`type` و`price_min` و`price_max`. حجم الصفحة الافتراضي 15 والحد الأقصى 100.
- أرسل `infinite=1` لاستخدام cursor pagination المناسبة للتمرير اللانهائي؛ حد الصفحة في هذا الوضع 50. الترتيب ثابت حسب `created_at` ثم `id` لتقليل تكرار النتائج عند إضافة عقارات جديدة. pagination العادية مناسبة للوحة المكتب التي تحتاج أرقام الصفحات وإجمالي النتائج.
- `GET /api/v1/properties/{id}` و`GET /api/v2/properties/{id}`: تفاصيل العقار.
- `GET /api/v1/home` و`GET /api/v2/home`: العقارات المميزة وعدد العقارات المتاحة في كل محافظة.
- `POST` و`PUT` و`DELETE /api/v1/properties` أو V2 محمية عبر Sanctum. أرسل رمزًا صالحًا في ترويسة `Authorization: Bearer ...`.

كل الاستجابات تمر عبر Resources. العمولة والملاحظات الداخلية لا تظهران في الاستجابات، ورقم المالك لا يظهر إلا للمستخدم المسجل. يقيّد Global Scope نتائج الزائر بالعقارات المعتمدة والمتاحة، ويستطيع مستخدم المكتب رؤية عقارات مكتبه وإدارتها دون تعديل عقارات مكتب آخر.

## الكاش

Redis هو مخزن الكاش الافتراضي. تُخزّن العقارات المميزة دقيقتين، كما تُخزّن أعداد العقارات لكل محافظة دقيقتين ضمن وسم مستقل للمحافظة. تفاصيل العقار لها مفتاح موحد `property:{id}` ومدة خمس دقائق؛ الكاش يحتفظ ببيانات العقار وليس JSON مختلفًا لكل إصدار API.

عند حفظ عقار أو حذفه، تُمسح تفاصيله فورًا، وتُبطل مجموعة المحافظة الحالية والسابقة عند تغيير المحافظة. تُبطل العقارات المميزة أيضًا. وسوم Redis تسمح بمسح بيانات المحافظة المتأثرة دون مسح بيانات محافظة أخرى أو حفظ قائمة مفاتيح يدوية. نتائج البحث ذات التركيبات الكثيرة من الفلاتر لا تُخزّن.

## البنية والاختبارات

Controllers رفيعة والمنطق المشترك في `PropertyService` و`HomeService`. مصدر بيانات العقارات خلف `PropertyRepository` مربوط في Service Provider. Resources تعرض العلاقات فقط عندما تكون محمّلة، والاستعلامات تستخدم eager loading لتفادي N+1. الصور وشعار المكتب يستخدمان علاقة polymorphic، والأنواع الثابتة ممثلة بـEnums والفلاتر بـLocal Scopes، مع فهارس لأعمدة التصفية.

لتشغيل الاختبارات بعد تثبيت الحزم:

```bash
composer test
```

أو داخل Docker:

```bash
docker compose exec app php artisan test
```

تستخدم اختبارات Feature قاعدة SQLite داخل الذاكرة ومخزن كاش array، فلا تحتاج Redis للاختبارات الأساسية.

## قبل الإنتاج

هذا مشروع تعليمي يحتاج مراجعة إعدادات التشغيل قبل النشر. أضف آلية دخول وإصدار رموز مناسبة، ورفع صور حقيقيًا، وصلاحيات إدارية لاعتماد العقارات، ومحدد معدل الطلبات، ومراقبة، وTLS وأسرار إنتاجية. لا ترفع `.env` أو رموز Sanctum التجريبية إلى مستودع عام.
