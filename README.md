# دارنا — واجهة API-first للعقارات

مشروع Laravel 11 تجريبي يطبّق API بإصدارين متزامنين (`/api/v1` و`/api/v2`) فوق منطق أعمال مشترك. V1 يبقي السعر رقمًا مع حقل العملة المنفصل، بينما V2 يعيد السعر ككائن `{amount, currency}`. لكل إصدار Resources مستقلة، وبطاقات القوائم أخف من صفحات التفاصيل.

## التشغيل عبر Docker

المتطلبات: Docker وDocker Compose. من مجلد المشروع نفّذ:

```bash
cp .env.example .env
docker compose up --build
```

تُنشأ قاعدة البيانات وتُشغّل migrations وseeders عند بدء الحاوية. العنوان `http://localhost:8000`. بيانات العرض: `agent1@darna.test` وكلمة المرور `password`؛ يستخدم الـSeeder Sanctum token محفوظًا في `personal_access_tokens`. لا تستخدم بيانات العرض في بيئة إنتاج.

للتشغيل اليدوي يتطلب PHP 8.2+ وComposer وMySQL وRedis: `composer install` ثم `cp .env.example .env`، `php artisan key:generate`، `php artisan migrate --seed` و`php artisan serve`.

## المسارات

- `GET /api/v1/properties` و`GET /api/v2/properties`: التصفية بـ`province_id`, `offer_type`, `type`, `price_min`, `price_max` و`per_page` (حد أقصى 100). استخدم `infinite=1` للتصفح بـcursor pagination، بحد أقصى 50. الترتيب ثابت بـ`created_at,id` لمنع تكرار النتائج عند إدراج عقارات جديدة أعلى القائمة. بدّل `paginate()` العادية بلوحة المكتب لتحصل على أرقام الصفحات/الإجمالي، وفعّل `infinite=1` لتطبيق الهاتف.
- `GET /api/v1/properties/{id}` وV2: التفاصيل.
- `GET /api/v1/home` وV2: المميزة وعدد العقارات المتاحة حسب المحافظة.
- محمية بـSanctum: `POST`, `PUT`, `DELETE /api/v{1|2}/properties`. أرسل `Authorization: Bearer <token>`؛ الاختبار المحلي يأخذ الرموز من `personal_access_tokens` بعد seeding.

الاستجابات تستخدم Resource لكل إصدار. لا ترجع أعمدة الملاحظات الداخلية والعمولة أبدًا، ورقم المالك يضاف فقط لمستخدم موثّق. الموديل يخفيها احتياطيًا أيضًا. Global Scope يخفي غير المنشور/غير المتاح عن الزوار، بينما مستخدم المكتب يستطيع إدارة العقارات المرتبطة بمكتبه فقط.

## قرار التخزين المؤقت

- Redis هو الـcache store، مع Redis tags لتجميع النتائج حسب المحافظة. الصفحة الرئيسية تخزن العقارات المميزة وإحصاءات المحافظات دقيقتين لتوازن الحمل وحداثة الأرقام.
- تفاصيل العقار تخزن خمس دقائق بمفتاح موحّد `property:{id}`؛ نخزن نموذج/بيانات لا JSON خاصًا بإصدار، فتظل V1/V2 متسقتين في الكاش.
- عمليات الحفظ/الحذف تمسح تفاصيل العقار ووسوم المحافظة وبيانات الصفحة الرئيسية فورًا. Redis tags تتيح إبطال مجموعة المحافظة من دون حفظ قائمة مفاتيح. البحث متعدد الفلاتر غير مخزّن لتجنب تضخم التركيبات.
- Redis tags غير مدعومة في كل Cache drivers، لذا Redis شرط تشغيل لهذا التصميم.

## البنية

`Controllers` رفيعة، والمنطق في `PropertyService` و`HomeService`، ومصدر بيانات العقارات خلف `PropertyRepository` مربوط في Service Provider. الـResources لا تحمّل علاقات ضمنيًا (`whenLoaded`)؛ الاستعلامات تعمل eager loading للعلاقات اللازمة منعًا لـN+1. الصور وشعار المكتب علاقة polymorphic. أنواع العرض والحالة والعملات Enums، والفلاتر Local Scopes، وفهارس قاعدة البيانات تغطي أعمدة البحث الشائعة. أخطاء API موحدة بالعربية مع رموز HTTP مناسبة (422 للمدخلات، 403 للصلاحيات، 404 للمفقود).

## الاختبارات

```bash
docker compose exec app php artisan test
```

تشمل اختبارات Feature تمييز شكل السعر بين النسختين وحماية البيانات الخاصة. وسّعها لتغطية صلاحيات ملكية المكتب، cursor pagination، إبطال Redis، وطلبات الإنشاء والتعديل على بيئة الاختبار؛ اختبار الكاش يتطلب Redis المتاح ضمن Compose.

## ملاحظات قبل الإنتاج

هذا تسليم تعليمي قابل للتوسعة، وليس إعداد نشر إنتاجي: أضف آلية تسجيل دخول/إصدار tokens آمنة، رفع ملفات وصلاحيات تخزين للصور، أدوارًا/سياسات إدارية للموافقة على العقارات، معدل طلبات، مراقبة، وتهيئة TLS وأسرار التشغيل. يجب تشغيل Redis مع دعم tags.
